# 操作边界与排错

工具入口在完整仓库 `bin/wechat-launch-kit.cjs`。先定位实际仓库，不假设当前工作目录。用 `--help` 查看精确命令；清单及产物放在项目私有目录或仓库 `.local/`，不要将真实账号信息提交公开仓库。

## 当前页面优先

小游戏示例检查模板：场景 30–800 字符、玩法 50–800 字符、各系统 30–800 字符；场景 3 张、玩法 3 张、至少 3 系统各 1 张，PNG/JPG、60 KiB–5 MiB。它来自实践表单，不是永久通用规则。先核对当前账号页面，并在 `requirements` 记录出处、日期和变化。

系统可使用真实的两个自定义系统与设置系统；如果页面不允许重复自定义，核对限制，不虚构商店/货币。普通小程序不套小游戏表单。公开入口均在 `docs/sources.md`，禁止编造登录后台深链。

## 隐私错误

HTTP 200 不能代表业务成功。已观察过业务返回 `{"errcode":-10000400,"errmsg":"参数错误，请刷新页面重试"}`，未找到官方对具体字段的解释。保留文案，按提示正常刷新并用真实内容重试一次；若仍失败，整理脱敏截图、业务响应与最小复现给官方帮助。不要要求收集请求头、Cookie、token 或完整 HAR。

没有证据不能归因于认证中、名称空白或某自定义项；不要求为排错重复认证、支付、修改主体或误勾权限。后续提交成功也不能反推当时根因。工具被站点安全策略拦截时必须停止该路径，用截图/手工方案推进，不改走绕过方式。

## 外部证据

资料、保存、上传、提交、通过、发布各自记录；两层备案与资质另记。已提交审核中的当前事实不能写成“已上线”。外部信息来自用户时标明 `user-report`，自行读回为 `platform-readback`；不要把本地报告包装成外部验证。
