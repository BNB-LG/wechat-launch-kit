# 微信开发者工具 CLI：授权与成功判定

适用记录：微信开发者工具 **2.02.2609250**，核对日期 **2026-11-10**。以下来自本机官方安装程序的 `cli --help`、`cli upload --help`、`cli preview --help`、实现及实际操作观察，不推定其他版本行为相同。

官方入口：[命令行调用](https://developers.weixin.qq.com/miniprogram/dev/devtools/cli.html)、[HTTP 调用](https://developers.weixin.qq.com/miniprogram/dev/devtools/http.html)。本次未成功公开读取这两个页面，保留链接供复核；本文不把本机观察写成已核验的在线文档结论。

## 服务端口需要单独授权

该版本在服务端口关闭时会提示 `IDE service port disabled` 并直接退出。英文提示虽然包含 `enter y`，实际没有等待确认输入；普通终端和 TTY 均未进入确认流程。不要把发送 `y` 或反复运行命令当成已启用。

获得用户授权后，经开发者工具「设置 → 安全设置 → 服务端口」开启，再验证 CLI 是否能连接。`--port` 用于指定 IDE HTTP 服务端口，不是开启已关闭服务能力的开关。

服务端口、CLI 访问票据获取和全项目默认信任属于不同授权范围。只获准开启服务端口时，不自动开启票据获取，也不默认信任全部项目；单个项目的信任按该项目的授权处理。需要重启工具时，单独确认已有重启授权，避免中断其他工作。

## 登录、项目身份与运行能力分别核对

- `islogin` 成功只证明工具当前登录状态，不证明目标项目身份、上传权限或接口权限。
- 打开项目后核对实际目录对应的 `project.config.json`：目标 `appid`、`compileType` 和 `miniprogramRoot`。正式小程序与小游戏分别使用正确账号和项目类型，不能靠补壳掩盖类型错误。
- `open` 成功只证明打开请求完成，不证明编辑器、模拟器、编译或真机能力已经就绪。
- 正式 AppID 下的原生运行、隐私同意和位置回调需要各自实际验证；它们通过也不证明代码上传成功。

## 退出码不能代替上传结果

已观察到 CLI **退出码为 0，同时输出 `code: 10` 业务错误**，且没有生成二维码。因此不能仅凭进程正常退出、进度进入上传阶段或文件路径已指定，就标记成功。

| 操作 | 最低成功证据 |
|---|---|
| `preview` | 业务结果明确成功；本次预期的 QR 文件及已指定的 info 文件真实生成；微信扫码核对对应版本和页面。 |
| `upload` | 业务结果明确成功；已指定的 info 文件真实生成；在平台开发版本记录中读回对应版本与说明。 |

核对产物是否属于本次命令，避免把旧 QR 或旧 info 当成本次结果。info、QR、平台读回各自记录；缺少其中适用的一项就明确写出缺口。上传成功仍不等于提审、审核通过或发布。

严禁伪造成功状态、二维码、info 文件或平台记录来补足证据。业务错误、空产物或缺少平台读回时，保持失败或待确认状态。

## COS 与 `[object Object]` 错误

本次实际观察到预览和上传进入 COS 上传阶段后失败，最终只显示 `Error: [object Object]`。本机实现存在信息丢失路径：无 `message` 的 COS 错误对象可能被转成字符串，并在普通上传回退失败时覆盖后续错误文本。不是所有 COS 错误都会如此，也不能从这段文本恢复原始原因。

仅凭这个错误，不能归因于类目、位置权限、DNS、TLS 或代理。即使某个主机的 DNS/TLS 探测成功，也不能证明带授权的实际上传链路成功；历史网络错误不能直接归因于本次上传。

在本次核对版本的公开 CLI 帮助中，未找到明确支持的关闭 COS 或强制普通上传参数。`--debug` 增加初始化、端口与连接信息，未提供恢复上传原始错误对象的开关。不要猜参数、调用隐藏接口或修改安装文件绕开内部决策。

保留脱敏错误、工具版本、操作类型、时间、预期产物是否生成及平台读回结果。没有新证据或已验证修复时，不要反复重传；同一错误再次出现后，应停止盲目重试并明确当前阻塞。诊断材料不包含票据、Cookie、签名、请求体、完整带查询参数的 URL 或其他秘密。
