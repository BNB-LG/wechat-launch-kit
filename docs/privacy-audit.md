# 从代码事实开始写隐私

自动检索只能给候选。先记录本次代码版本与文件摘要，再阅读入口、平台适配、存储、网络及第三方 SDK 调用点，核查数据进入、使用、持久化、上传和删除的完整路径。`audit-source` 不执行代码，并会跳过依赖和构建文件；有这些内容时必须补审，尤其是广告、统计、插件和动态代码。

记录每种数据的名称、用途、获取方式、存储位置、保存期限、删除能力、源码证据；区分已实现和未来计划。也要检查实际运行网络，不把静态未检出等同于不存在。

| 情形 | 正确处理 |
|---|---|
| 没调用某项受控 API | 不为凑表单勾选手机号、位置、微信关系等无关类别 |
| 有其他真实信息处理 | 对照小游戏指南使用独立“自定义类型／其他”入口，填写真实用途 |
| 本地最高分 | 披露真实保存行为；不自动判成好友关系、排行榜，也不凭本地二字排除个人信息 |
| 仅窗口参数与即时触控 | 核对实际提取字段、是否存储或上传；不要臆造设备标识和轨迹采集 |
| 无自动过期代码 | 写真实保存机制；不能为了页面填 0 天、30 天或承诺自动删除 |
| 没有清空/删除入口 | 明确未实现，不把从最近列表移除等同于已验证清空数据 |
| 没有第三方 SDK | 仍核查依赖与打包结果，不复制别人的供应商名单 |

单个本地分数是否属于法律上的个人信息，需结合可识别性、关联数据和实际处理判断；这个工具不作法律裁定。实际处理个人信息时，按适用官方指南核对展示、处理前同意、授权上报及拒绝路径，不能因没有服务器就省略。

隐私文本入口、主动同意、受控 API 触发和后台选项是不同事项。勾选“处理用户信息”不自动证明必须或已经加开屏弹窗；没有受控 API 也不代表其他处理无需适配。若使用自定义授权弹窗，按官方要求展示真实隐私指引链接并验证拒绝路径。测试和后台审核结果各自留证。

建议人工审计交付：代码版本与摘要、候选列表的逐项结论、数据表、SDK 清单、实际网络观察、填写稿、真机授权与拒绝测试、尚未核实项。没有足够证据时保持 `auditStatus: "pending"`。

参考：[小游戏用户隐私保护](https://developers.weixin.qq.com/minigame/dev/guide/open-ability/privacy.html)、[小程序隐私指引内容](https://developers.weixin.qq.com/miniprogram/dev/framework/user-privacy/miniprogram-intro.html)。小程序文档可辅助理解通用栏目，不能替代小游戏运行时指南。
