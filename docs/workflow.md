# 从资料准备到真实发布

## 先判断账号分支

核对“小游戏还是小程序”“测试号还是正式号”“个人还是组织主体”和实际类目。小游戏源码通常使用 `game.js` / `game.json`；如果正式账号被识别为普通小程序并要求 `app.json`，先核对账号类型，不要为了掩盖分支错误加一个小程序外壳。测试号预览二维码不是长期公众入口。

小程序使用自身功能、隐私和版本审核路径，不强套小游戏三系统、适龄与游戏内容备案表。个人主体不套用单位授权书。身份信息、协议签署、账号绑定和支付由本人在官方页面确认；不收集登录秘密。

## 按真实实现写资料

1. 明确本次版本、实际引擎、游戏/功能分类、介绍、测试入口与更新说明。
2. 核查网络请求、登录、云开发、广告、支付、排行榜、分享、本地文件和存储。未来计划与当前能力分开写。
3. 小游戏按真实角色、情节和画面给适龄建议，建议不是评级结果。
4. 需要三系统时，可据实现使用两个自定义系统与一个设置系统；如果页面不允许重复自定义，保留文案并核对实际限制，不虚构货币/商城/兑换功能。
5. 截图来自同一版本微信运行环境，保留原图。场景、玩法及系统应拍到真实不同运行状态；不能重命名、重编码或加噪声骗过重复检测。

版本审核中的选填宣传图与内容说明必填截图不是同一项。后台出现 Apple 开发者账号字段时按真实邮箱填写；官方指引允许邮箱，不据此推断必须购买 Apple 会员，不把客服邮箱擅自当成 Apple 账号。

## 网络类型及备案

本地单人运行只是技术事实；平台“单机”选项应读取本账号当前声明。分别核对允许功能、签署要求、适用备案层级、未来广告和网络能力变更。公开通用指南与账号新入口可能存在差异，不拿旧示例图否定用户当前页面，也不把某账号经历推广为普遍豁免。

用户已经确认签署完成，就记录证据继续准备，不重复要求签署或付款。声明全文未知可以标注未验证，但不能仅因缺少全文就阻止与其无关的字段整理。发布条件仍看账号当前正式说明及实际状态。

## 每一步分别留证

| 状态 | 可支持的证据 | 不能据此声称 |
|---|---|---|
| 本地草稿 | 生成的文本、图片及校验结果 | 后台已保存 |
| 后台保存 | 页面保存反馈与回读 | 代码已上传或已提审 |
| 开发版上传 | 上传成功且版本管理读回具体版本 | 审核通过 |
| 提交／审核中 | 提交回执或对应版本审核状态；标注用户报告/代理读回 | 已公开上线 |
| 审核通过 | 对应版本通过状态 | 已执行发布 |
| 公开发布 | 线上版本读回；另测普通用户访问 | 所有设备、入口和能力均正常 |

这些是证据标签，不是保证所有分支严格按此顺序的流程机。资质、小游戏内容备案与小程序工信备案独立记录，不相互替代。用户明确报告“已经审核中”时更新为 submitted/user-report，不继续重复要求提交。

## 后台错误与安全阻断

实际见过协议设置请求 HTTP 200、业务体 `{"errcode":-10000400,"errmsg":"参数错误，请刷新页面重试"}`。这只证明该次业务失败，未找到官方具体字段对应解释；不能认定由认证中、开发者名称空白或本地最高分项导致，也不能声称已解决。

先保存已填文本，按页面指示正常刷新、重新进入后用相同真实内容重试一次。仍失败则保留最小复现、脱敏截图和业务响应，走官方帮助。不要反复修改真实主体、不重办认证、不勾选不存在的权限；不收集 Cookie、请求头、token、完整 HAR。账号标识若客服需要，由用户在官方渠道提供。

如果浏览器或工具的安全策略拒绝访问，停止受阻路径，转为用户提供的脱敏字段截图和手工填写指导。不要改用隐藏请求、Cookie、CDP、AppleScript 或其他绕过路径。本项目不提供任何后台自动上传、自动签署、自动提交能力。
